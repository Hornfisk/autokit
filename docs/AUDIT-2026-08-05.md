# Autokit end-to-end audit — 2026-08-05

Repo at `0ee0bce` (v0.5.4). Baseline: **104 tests pass**, release build OK,
`cargo fmt --check` **dirty**, `cargo clippy` **~48 distinct warnings**,
no CI beyond release-on-tag.

Severity key: **P0** = ships broken / can panic the audio thread ·
**P1** = wrong behaviour or data loss · **P2** = correctness-adjacent, quality ·
**P3** = polish.

---

## P0 — audio-thread panics reachable from user data

### 1. `PatternBank::active` is unvalidated after deserialization
`sequencer.rs:216` `active_pattern()` indexes `self.patterns[self.active]` with
no bounds check. `active` arrives from `#[persist]` JSON and from user preset
files (`preset.rs:291` clamps it, but `PatternBank` deserialized directly via
serde — e.g. the `pattern_bank_serializes_roundtrip` path — does not).
An out-of-range `active` panics on the audio thread.

### 2. `Lane::pad_index` is unvalidated after deserialization
`sequencer.rs:619` (`fire_step_from_bank`, **the shipping path**) does
`trigger_flags[pad_index].fetch_add(...)` with no bounds check, and
`sampler.rs:185` does `&kit.pads[pad_index]`. A preset JSON with
`pad_index: 99` panics the audio thread.

Note the dead path `fire_step` (`sequencer.rs:746`) **has** the guard
(`if pad_index < trigger_flags.len()`). The guard is on the code that never
runs; the shipping path is unguarded.

### 3. `ConditionTrig::Every(0)` divides by zero
`sequencer.rs:363` `self.loop_count % n as u64`. The UI only offers N ∈ {2,4,8},
but `Every(0)` is representable in JSON and panics the audio thread.

### 4. `Reverb` comb/allpass buffers are unguarded against zero length
`fx.rs:277` `self.buf[self.idx]` — `Comb::new()` leaves an empty `Vec` and
`tick()` has no `is_empty` guard, unlike `Delay::process_sample` which does
guard (`fx.rs:200`). Any path reaching `process()` before `prepare()`, or a
sample rate low enough that `tuning * scale` truncates to 0, panics.

### 5. `receive_scan_result` takes a **blocking** lock on the audio thread
`plugin.rs:477` `let mut shared = self.shared.lock();`. Every other audio-thread
access in the file uses `try_lock()`. The GUI holds this mutex every frame to
build its snapshot, so this call can block the audio thread for a full GUI
frame. It also runs `history.push()` and `update_all_waveforms()` (allocating,
O(pads × sample length)) inside that critical section — wrapped in
`permit_alloc`, so the assertion is silenced rather than the problem fixed.

## P1 — wrong behaviour / data loss

### 6. Delay-time readout disagrees with the delay actually played
Two different quantizations of the same 0..1 parameter:

| | expression | buckets |
|---|---|---|
| display (`plugin.rs:131`) | `(v * 4.0).round()` | 5 uneven buckets |
| audio (`plugin.rs:1126`)  | `(v * 3.0).round()` | 4 even buckets |

At `v = 0.75` the readout says **1/4** while the audio plays **1/8**. At
`v = 0.4` the readout says **1/8** while the audio plays **1/16**. The two
agree only by coincidence at the default 0.5. The audio mapping is the correct
one; the display mapping is the bug.

### 7. Preset / config / standalone-state writes are non-atomic
`preset.rs:85`, `preset.rs:188`, `config.rs:80` all use `std::fs::write`, which
truncates before writing. A crash or power loss mid-write leaves a truncated
JSON and the user's kit is gone. `save_standalone_state` runs automatically, so
this is not a rare path. Fix: write to a sibling `.tmp` then `rename()`.

### 8. Preset/pattern storage path is wrong on macOS and Windows
`preset.rs:53` `dirs_next()` only understands `XDG_DATA_HOME` / `HOME`. On
Windows `HOME` is usually unset, so it falls through to the **relative** path
`.local/share` — resolved against the process CWD, i.e. the DAW's install
directory. `config.rs:90` already does this correctly per-platform; `preset.rs`
was never updated to match. Windows and macOS binaries ship in CI, so this
affects released builds.

### 9. `looks_like_oneshot` panics on NaN input
`library.rs:455` `partial_cmp(&b.abs()).unwrap()`. A file that decodes to NaN
kills the scanner thread (background, so not an audio-thread panic — but the
scan silently never completes). Use `f32::total_cmp`.

### 10. No `Plugin::reset()` implementation
nih-plug calls `reset()` on transport discontinuities. Autokit doesn't
implement it, so compressor envelope, limiter envelope, RMS history, delay
buffer, and reverb tails all carry across a stop → seek → play. `MasterBus` and
`FxBus` already expose `prepare()`, which is exactly the hook `reset()` needs.

## P2 — dead code that makes the tests lie

### 11. The tested audio paths are not the shipped audio paths
Two parallel implementations exist; the tests cover the dead one.

| tested (dead in prod) | shipped (untested) |
|---|---|
| `VoicePool::process` | `VoicePool::process_sends` |
| `Sequencer::process_buffer` + `fire_step` + `step_duration_samples` | `Sequencer::process_buffer_with_patterns` + `fire_step_from_bank` + `step_duration_with_swing` |

The four-bus FX routing (`process_sends`) — the thing v0.5.0 was built around —
has **zero** test coverage. And, per finding #2, the dead path carries a bounds
guard the live path lacks, which is exactly the kind of drift duplication
causes.

### 12. `FxBus::process_sample` / `FxTargets` are dead, and the module doc is wrong
`fx.rs:1-13` documents the chain as `input → dj_filter → delay → reverb`.
Nothing calls `FxBus::process_sample`; `plugin.rs` reaches into
`fx_bus.reverb` / `.delay` / `.dj_filter` individually and runs a four-bus send
architecture instead. The doc comment describes a routing that does not exist.

### 13. `main.rs` and `lib.rs` duplicate the whole module tree
Both declare the identical 30-module tree, so the crate compiles twice and
every clippy warning is reported twice. Adding a module means editing two files
that can silently drift. Fix: `crate-type = ["cdylib", "rlib"]` and have
`main.rs` use the library.

### 14. Other dead code flagged by clippy
`scanner::scan_folder`, `scanner::filter_by_duration`, `scanner::MAX_DURATION_SECS`,
`SampleLibrary::build`, `SampleLibrary::random_from`, `clone_for_dice`,
`SampleCategory::all`, `MasterAutomation::any_recorded`, `StepSmoother::current`,
`ToggleStep`/`SelectStep`/`CopyStep`/`PasteStep`/`ToggleView` enum variants,
`pad_name` and `screen_pos` fields.

## P2 — hygiene

### 15. `cargo fmt --check` is dirty
Many files. No `rustfmt.toml` pinning a style.

### 16. ~48 distinct clippy warnings
`needless_range_loop`, `manual_flatten`, `unwrap_or_default`, `len_zero`,
`collapsible_if`, `if_same_then_else`, `derivable_impls`,
`items_after_test_module`, `unused_enumerate_index`, `needless_borrow`,
`redundant_locals`, `single_match`, `unnecessary_map_or`,
`manual_is_multiple_of`, `too_many_arguments` (up to 16 args), plus 5 unused
variables and 2 unused imports.

### 17. There is no CI that runs tests
`.github/workflows/release.yml` only fires on `v*` tags and only builds. Nothing
runs `cargo test`, `cargo clippy`, or `cargo fmt --check` on push or PR. A
red-tests commit reaches `master` unnoticed.

### 18. `VoicePool::trigger` takes 12 positional arguments
`sampler.rs:170`. Five are `Option<...>` p-locks and three are lane defaults;
every call site is a wall of `None, None, None, None, None`. A `TriggerParams`
struct removes an entire class of argument-order bug.

## P3 — metadata, docs, identity

### 19. `CLAP_ID` still says `com.rexist.autokit` — **needs your decision**
`plugin.rs:1187`. This is the last REXIST string in the tree
(`memory: todo_autokit_rexist_vendor_leak`). Changing it orphans the plugin in
any existing DAW project that already loaded Autokit by CLAP ID — the
Slammer→Niner problem. Not a quiet edit.

### 20. `URL` and `EMAIL` are empty strings
`plugin.rs:518-519`. Hosts show these in the plugin info panel. For a shipped
Hyperfocus DSP product they should point at the site and a support address.

### 21. `CLAP_DESCRIPTION` says "AI-powered"
`plugin.rs:1189` "AI-powered drum machine with sample map visualization". There
is no AI in it — it's FFT feature extraction plus a threshold classifier. It
also contradicts `Cargo.toml`'s own description ("Sample-based drum machine
plugin with spectral analysis"), which is accurate.

### 22. CHANGELOG stops at 0.5.2
`Cargo.toml` says 0.5.4. Missing entries for 0.5.3 (crest-factor gate) and
0.5.4 (vendor rebrand). No `v0.5.4` tag, so shipped binaries still report the
old vendor.

### 23. Repo contains stray files
`Development Plan for Lightweight Linux Drum Plugin.docx` and `autokit.ctx` are
tracked at the repo root. `setup-deps.py` sits at root with no README reference.

## Deferred / noted, not proposed as fixes

- **Resampler group delay.** `audio_file.rs:95` runs a 256-tap sinc without
  compensating its ~128-sample group delay, so resampled samples start ~2.9 ms
  late relative to native-rate ones. Audible only when layering a resampled and
  a non-resampled hit; fixing it means trimming `sinc_len/2` from the head and
  is worth a listening test before changing.
- **`sample_by_flat_index` rebuilds and sorts the category list per call.**
  O(n log n) per lookup on a GUI hot path. Perf, not correctness.
- **Auto-makeup gain is signal-independent** (`master_bus.rs:113`) — at
  threshold −40 dB it applies +15 dB regardless of content. Defensible as a
  design choice; flagging only so it's a choice and not an accident.

## Deliberately not done

- **`EMAIL` is still empty.** Setting it publishes a support address in every
  host's plugin panel, and picking which address that is (the Hyperfocus
  support alias vs. anything tied to a personal identity) is a decision worth
  making on purpose. The CLAP support URL points at GitHub issues meanwhile.
- **Stray repo files.** `Development Plan for Lightweight Linux Drum Plugin.docx`,
  `autokit.ctx` and `setup-deps.py` are still tracked at the repo root. They
  look intentional-but-stale rather than accidental, and deleting tracked
  files is the author's call.
- **Five UI draw functions still take 9–11 arguments** (`knob`,
  `knob_inline`, `draw_collapsed_from_snapshot`, `draw_expanded_from_snapshot`,
  `draw_map`), now carrying an explicit `#[allow]` with rationale. The 16-arg
  `draw_toolbar_snapshot` was converted because it had five consecutive
  `bool`s that could be transposed silently; the rest have no same-typed
  neighbours, so a view struct would add indirection without removing a hazard.
- **No release cut.** `Cargo.toml` says 0.5.5 and the CHANGELOG entry is marked
  unreleased. Tagging is a separate, deliberate step.
- The three "deferred / noted" items above (resampler group delay,
  `sample_by_flat_index` cost, signal-independent auto-makeup) remain open by
  design — each needs a listening test, not a code change.
